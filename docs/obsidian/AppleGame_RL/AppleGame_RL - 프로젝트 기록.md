# AppleGame_RL - 프로젝트 기록

## 목표
- 사과게임(10×17, 합이 10인 직사각형 지우기, 120초)을 자동으로 푸는 AI
- 처음 목표 120점 → **실제 게임 140 / 170점 달성**

## 타임라인
| 단계 | 한 일 | 결과 | 배운 것 |
|---|---|---|---|
| v1 | PPO / DQN, 마스킹 없음, 4~5시간 학습 | 고득점 실패 | [[행동 마스킹과 보상 설계가 알고리즘보다 먼저다]] |
| 진단 | 무작위/탐욕 기준선 측정 | 무작위 103, 탐욕 114 | [[기준선부터 만든다]] |
| v2 | 배치 환경 + 마스킹 PPO, 행렬곱 환경 | 정책 110~114 (탐욕 못 넘음) | [[모든 사각형 합을 행렬곱 한 번으로]] |
| 원인 분석 | 한 수 효과 vs 운 측정 | 신호 약 1점 vs 운 ±15점 | [[신호 대 잡음으로 강화학습 실패를 진단한다]] |
| v3 | AlphaZero식 MCTS 자기대국 (CPU/GPU) | MCTS 122~124, 정책은 탐욕 수준 | [[결과를 계산할 수 있으면 학습보다 탐색]] |
| v4 | 롤아웃 탐색 (학습 없음) | 130 | [[결과를 계산할 수 있으면 학습보다 탐색]] |
| 실제 보드 | 스크린샷 10장 분석, 생성 규칙 역추정 | 두 버전 발견, 균등 분포 가정이 틀림 | [[학습 분포가 실제와 같은지 먼저 확인한다]] |
| 인식 | 템플릿 매칭 숫자 인식 | 70가지 중 69가지 100% | [[범용 OCR 대신 템플릿 매칭]] |
| 실전 | 화면 캡처 + 롤아웃 + 실제 마우스 | **140점 / 1분 3초** | [[실전 연결은 시뮬레이터로 검증한다]] |

## 핵심 수치
- 균등 보드: 무작위 103 / 탐욕 114 / PPO+빔 125.6 / AZ+MCTS256 124.3 / 롤아웃 130
- 실제 납작한 사과 보드 6장: 탐욕 121.7 / MCTS 120.8 / **롤아웃 130.0**
- 실제 게임 1판: **140 / 170**

## 중요한 결정과 이유
1. **PPO → AlphaZero → 롤아웃 탐색**: PPO는 신호가 운에 묻혔다. AZ의 가치망은 실제 보드에서 흔들렸다. 롤아웃은 학습 없이 결과를 직접 계산하므로 분포가 바뀌어도 흔들리지 않았다.
2. **생성 보드 → 실제 보드 분석**: 실제 게임은 합이 항상 10의 배수였고, 둥근 사과 버전은 배치에도 구조가 있었다.
3. **OCR → 템플릿 매칭**: 글꼴과 칸 위치가 고정이라 더 빠르고 정확했다.
4. **실전 검증**: 마지막 수 직후 종료 창, 고해상도에서 꼭지가 따로 잡히는 문제, DPI 문제를 하나씩 재현하고 고쳤다.

## 남은 과제

- [ ] 정책망 단독으로 탐욕 넘기 (정책 헤드 구조 `head="rich"` 검증, GPU 필요)

## 포트폴리오 한 줄
> 강화학습(PPO)이 탐욕 규칙도 못 넘는 원인을 신호 대 잡음으로 측정하고, 게임이 결정적이라는 특성을 근거로 탐색 기반으로 전환했다. 실제 게임 보드의 생성 규칙을 역추정하고, 화면 인식과 자동 입력까지 연결해 실제 게임에서 140/170점을 냈다.
